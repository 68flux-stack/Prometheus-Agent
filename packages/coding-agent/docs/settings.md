# Settings

Prometheus uses JSON settings files with project settings overriding global settings.

| Location | Scope |
|----------|-------|
| `~/.prometheus/agent/settings.json` | Global (all projects) |
| `.prometheus/agent/settings.json` | Project (current directory) |

Edit directly or use `/settings` for common options.

## All Settings

### Model & Thinking

| Setting | Type | Default | Description |
|---------|------|---------|-------------|
| `defaultProvider` | string | - | Default provider (e.g., `"anthropic"`, `"openai"`) |
| `defaultModel` | string | - | Default model ID |
| `defaultThinkingLevel` | string | `"xhigh"` | `"off"`, `"minimal"`, `"low"`, `"medium"`, `"high"`, `"xhigh"` |
| `hideThinkingBlock` | boolean | `true` | Hide thinking blocks in output |
| `thinkingBudgets` | object | - | Custom token budgets per thinking level |

```json
{
  "thinkingBudgets": {
    "minimal": 1024,
    "low": 4096,
    "medium": 10240,
    "high": 32768
  }
}
```

### Update Checks

Stable builds fetch the release manifest at `https://pub-728493de92a943e2a9b2d17b4719f318.r2.dev/latest.json`. Beta builds fetch `beta.json` and continue following beta updates. Override the base URL with `PROMETHEUS_DOWNLOAD_BASE_URL`.

Set `PI_SKIP_VERSION_CHECK=1` to disable the Prometheus version update check. Use `--offline` or `PI_OFFLINE=1` to disable startup network operations, including update checks and package update checks.

The stable `latest.json` and beta `beta.json` manifests use the same JSON shape:

```json
{
  "version": "0.73.1",
  "package": "prometheus",
  "tarball": "releases/v0.73.1/prometheus-0.73.1.tgz"
}
```

`version` is required. `package` is optional and may also be named `packageName`; it defaults to the current package name. `tarball` is optional; when present, Prometheus installs that tarball instead of the package name. Relative tarball paths resolve against `PROMETHEUS_DOWNLOAD_BASE_URL`.

### Pseudonymous usage analytics

Prometheus sends pseudonymous, aggregate usage and performance events to Prometheus Intellect. These events include version and operating-system category, onboarding outcome and duration, execution mode (`interactive`, `print`, `json`, `rpc`, or `acp`), run outcomes, TTFT and latency, prompt and turn counts, token usage, tool success counts, retries, and compactions.

Prometheus does not send prompts, responses, thinking, tool arguments or results, command text, filenames, paths, repository information, environment variables, credentials, raw error messages, hostnames, usernames, emails, or hardware identifiers. A random installation ID is stored as `telemetry.json` in the configured agent directory (normally `~/.prometheus/agent/`).

Telemetry can be disabled globally or for an individual project. Project settings can only further restrict telemetry: they cannot re-enable a global opt-out or suppress the global one-time disclosure.

| Setting | Type | Default | Description |
|---------|------|---------|-------------|
| `telemetry.enabled` | boolean | `true` | Send pseudonymous aggregate usage and performance events |

Disable analytics with any of:

```json
{
  "telemetry": {
    "enabled": false
  }
}
```

```bash
PROMETHEUS_TELEMETRY=0 prometheus
DO_NOT_TRACK=1 prometheus
prometheus --offline
```

`PROMETHEUS_TELEMETRY_ENDPOINT` overrides the ingestion endpoint for development and self-hosted deployments.

### Retry

| Setting | Type | Default | Description |
|---------|------|---------|-------------|
| `retry.enabled` | boolean | `true` | Enable automatic agent-level retry on transient errors |
| `retry.maxRetries` | number | `3` | Maximum agent-level retry attempts |
| `retry.baseDelayMs` | number | `2000` | Base delay for agent-level exponential backoff (2s, 4s, 8s) |
| `retry.provider.timeoutMs` | number | SDK default | Provider/SDK request timeout in milliseconds |
| `retry.provider.maxRetries` | number | SDK default | Provider/SDK retry attempts |
| `retry.provider.maxRetryDelayMs` | number | `60000` | Max server-requested delay before failing (60s) |

When a provider requests a retry delay longer than `retry.provider.maxRetryDelayMs` (e.g., Google's "quota will reset after 5h"), the request fails immediately with an informative error instead of waiting silently. Set to `0` to disable the cap.

```json
{
  "retry": {
    "enabled": true,
    "maxRetries": 3,
    "baseDelayMs": 2000,
    "provider": {
      "timeoutMs": 3600000,
      "maxRetries": 0,
      "maxRetryDelayMs": 60000
    }
  }
}
```

### Shell

| Setting | Type | Default | Description |
|---------|------|---------|-------------|
| `shellPath` | string | - | Custom shell path (e.g., for Cygwin on Windows) |
| `shellCommandPrefix` | string | - | Prefix for every bash command (e.g., `"shopt -s expand_aliases"`) |
| `npmCommand` | string[] | - | Command argv used for npm package lookup/install operations (e.g., `["mise", "exec", "node@20", "--", "npm"]`) |

```json
{
  "npmCommand": ["mise", "exec", "node@20", "--", "npm"]
}
```

`npmCommand` is used for all npm package-manager operations, including installs, uninstalls, and dependency installs inside git packages. Use argv-style entries exactly as the process should be launched. When `npmCommand` is configured, git package dependency installs use plain `install` to avoid npm-specific flags in wrappers or alternate package managers.

Normally the package manager's global modules location is queried using `root -g`. As a special case, if the first element of `npmCommand` is `"bun"`, the modules location will instead be queried with `pm bin -g`.

### Execution permissions

Use `/permissions [plan|workspace|unrestricted]` or the configurable `app.permissions.cycle` keybinding to change modes. The default is `unrestricted` for compatibility.

- `plan` permits read-only file exploration and the bundled web-search skill while denying filesystem writes and general network access at the kernel-process boundary. On Windows, IPython remains available while its write operations, subprocesses, other network access, and background commands are blocked.
- `workspace` allows writes only inside the workspace and configured `writeRoots`. It is a fence, not a wall: on Windows the kernel can call `request_directory_access("<directory>", "<why>")`, which shows you an accept/deny prompt in the transcript. An accepted directory stays open for the rest of the session and is never written to settings; a denial is reported back to the model as restricted.
- `unrestricted` preserves the existing unsandboxed behavior and displays a warning in `/permissions status`.

Linux and macOS use the `srt` OS sandbox backend. Windows supports all three modes through Prometheus's application permission boundary; `workspace` mode remains advisory for filesystem access performed by child processes because Windows does not yet have an OS filesystem backend. `ask` command rules block execution until policy is explicitly changed; they do not silently fall through.

```json
{
  "permissions": {
    "mode": "workspace",
    "writeRoots": ["/tmp/project-cache"],
    "rules": [
      { "target": "command", "pattern": "git push*", "action": "ask" },
      { "target": "network", "pattern": "github.com", "action": "allow" },
      { "target": "filesystem.write", "pattern": ".env", "action": "deny" }
    ]
  }
}
```

Rules are ordered and use last-match-wins. Targets are `tool`, `command`, `filesystem.read`, `filesystem.write`, and `network`; actions are `allow`, `ask`, and `deny`. Project-specific behavior can still be layered through extension hooks.

### Daemon

| Setting | Type | Default | Description |
|---------|------|---------|-------------|
| `idleEvictionMinutes` | number or `"off"` | `90` | Idle threshold in minutes for whole-tree worker eviction and individual idle-child passivation; `"off"` disables both. |

### Resources

These settings define where to load extensions, skills, prompts, and themes from.

Paths in `~/.prometheus/agent/settings.json` resolve relative to `~/.prometheus/agent`. Paths in `.prometheus/agent/settings.json` resolve relative to `.prometheus/agent`. Absolute paths and `~` are supported.

| Setting | Type | Default | Description |
|---------|------|---------|-------------|
| `packages` | array | `[]` | npm/git packages to load resources from |
| `extensions` | string[] | `[]` | Local extension file paths or directories |
| `skills` | string[] | `[]` | Local skill file paths or directories |
| `prompts` | string[] | `[]` | Local prompt template paths or directories |
| `themes` | string[] | `[]` | Local theme file paths or directories |
| `enableSkillCommands` | boolean | `true` | Register skills as `/skill:name` commands |
| `enableBuiltinSkills` | boolean | `true` | Load built-in skills shipped with prometheus |
| `bundledSkills.websearch` | boolean | `true` | Load the built-in `websearch` skill |

Arrays support glob patterns and exclusions. Use `!pattern` to exclude. Use `+path` to force-include an exact path and `-path` to force-exclude an exact path.

Disable the built-in `websearch` skill while keeping normal skill discovery enabled:

```json
{
  "bundledSkills": {
    "websearch": false
  }
}
```

#### packages

String form loads all resources from a package:

```json
{
  "packages": ["pi-skills", "@org/my-extension"]
}
```

Object form filters which resources to load:

```json
{
  "packages": [
    {
      "source": "pi-skills",
      "skills": ["brave-search", "transcribe"],
      "extensions": []
    }
  ]
}
```

See [packages.md](packages.md) for package management details.

## Project Overrides

Project settings (`.prometheus/agent/settings.json`) override global settings. Nested objects are merged:

```json
// ~/.prometheus/agent/settings.json (global)
{
  "theme": "dark",
  "compaction": { "enabled": true, "thresholdPercent": 75, "reserveTokens": 16384 }
}

// .prometheus/agent/settings.json (project)
{
  "compaction": { "reserveTokens": 8192 }
}

// Result
{
  "theme": "dark",
  "compaction": { "enabled": true, "reserveTokens": 8192 }
}
```
